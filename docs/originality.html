Is it unique? And has it been done?

A straight answer, checked against what's already out there. Every building block here exists in other projects — but the specific way they're combined, and the safety design, is not something I found as a single existing project.

Not the first local AI assistant — but a distinctive combination, with a safety model most hobby projects skip.

Local voice assistants on a Raspberry Pi with Ollama are common. An ESP32 talking to a laptop server is common. What's uncommon is doing all three tiers at once — laptop brain, Pi hub, ESP32 sensor — tied together by a formal device protocol where the AI is never allowed to issue a command. That last part is an active research topic, rarely seen in a personal build.

Honest breakdown

What already exists, and what sets this apart.

Already common

  • Local LLM on a Pi/laptop via Ollama — many tutorials and projects.
  • Voice assistant (Whisper speech-to-text + a local model) — well-trodden.
  • ESP32 + laptop server over Wi-Fi for a smart device — a known pattern.
  • MQTT for device messaging — the standard choice for IoT.
  • Vision from a local model — increasingly common with small VL models.

Distinctive here

  • Three coordinated tiers — laptop + Pi + ESP32 working as one system, not a single board.
  • A formal protocol — devices declare their abilities (a capability manifest) with a risk level; commands have a lifecycle and an expiry.
  • The LLM never commands hardware — only fixed, server-side whitelists do. This is the safety idea research papers are built around.
  • Input from everywhere — touch pad, web page, phone camera, both webcams, and voice, all into one brain.
  • Proof, not promises — 100 tests, a live end-to-end pass, a reproducible security report.

Closest things that already exist

In fairness, these overlap with parts of the project:

xiaozhi-esp32-server — a mature open-source backend for ESP32 voice devices, with vision and MQTT. The closest single match, but it centres on ESP32 clients talking to one server, not a laptop + Pi + ESP32 system with a capability protocol.
Home Assistant + Ollama + Whisper + Piper — a powerful local-voice home-automation stack. More established and feature-rich, but a different goal: whole-home automation, not a small device framework with a safety-first command model.
Research on safe LLM robotics (SafeGate, RoboGuard) — formalises exactly the idea at this project's core: a deterministic gate so an LLM can't issue an unsafe command. These are academic papers, which makes it notable that a personal build applies the same principle.

The bottom line

No, it hasn't been "done before" as one package — I didn't find an existing project that combines a three-tier laptop/Pi/ESP32 design, a formal capability protocol, and a safety model that keeps the AI out of the command path. Yes, every ingredient exists elsewhere, so the originality is in the architecture and the discipline, not in inventing a new technology. For a personal project, that's a genuinely strong and uncommon combination — and the safety stance is ahead of most hobby builds. Where it would stand out even more: a reusable, documented device SDK others could plug new hardware into (the protocol is already most of the way there).
